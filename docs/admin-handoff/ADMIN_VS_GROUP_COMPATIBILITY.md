# BÁO CÁO ĐỐI CHIẾU TƯƠNG THÍCH GIỮA ADMIN VÀ CODE NHÓM (ADMIN VS GROUP COMPATIBILITY MATRIX)

> **Dự án:** CafeOrder  
> **Phạm vi đối chiếu:** So sánh trực tiếp mã nguồn nhánh `ui_admin` (Models, Repositories, Services, Admin Views) với mã nguồn Client / Server / KDS hiện có của nhóm (`ClientMain`, `ClientController`, `ServerMain`, `CafeServerService`, `ClientSocketService`, `MenuRepository`, `MessageProtocol`, `MessageType`).  
> **Nguyên tắc:** Giữ nguyên toàn bộ code Client/Server/KDS của nhóm trong giai đoạn này; lập bảng phân loại rõ ràng để cả nhóm thống nhất khi ghép nhánh.

---

## 1. HỆ THỐNG PHÂN LOẠI TƯƠNG THÍCH (5 NHÓM)

Mỗi điểm khác biệt dưới đây được gắn đúng 1 trong 5 nhãn phân loại:
1. **`[COMPATIBLE]` — Tương thích hoàn toàn:** Dùng chung class/method hiện tại mà không cần chỉnh sửa.
2. **`[ADAPTER_NEEDED]` — Có thể viết lớp chuyển đổi (Adapter):** Khác biệt nhỏ về tên gọi hoặc tham số, xử lý được bằng hàm chuyển đổi/constructor phụ.
3. **`[GROUP_DECISION]` — Cần nhóm chốt quy ước chung:** Có 2 hướng thiết kế giữa code cũ và chuẩn nghiệp vụ mới, cần nhóm biểu quyết.
4. **`[SERVER_DB_UPGRADE]` — Cần nâng cấp ở Server/DB khi tích hợp:** Code Client/Server hiện tại đang hardcode hoặc thiếu trường dữ liệu so với yêu cầu thực tế.
5. **`[ADMIN_UI_ONLY]` — Chỉ dùng nội bộ trong Admin UI:** Không ảnh hưởng tới luồng TCP hay Client/KDS.
